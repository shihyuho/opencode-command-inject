# Codebase Structure

**Analysis Date:** 2026-03-30

## Directory Layout

```text
opencode-command-inject/
├── `index.ts`                    # Public package entrypoint; re-exports plugin symbols
├── `package.json`                # Package metadata, scripts, dependency manifest
├── `scripts/`                    # Repository maintenance CLI, currently schema generation
├── `src/`                        # All shipped TypeScript implementation and tests
│   ├── `plugin.ts`               # Plugin factory/orchestrator
│   ├── `plugin/`                 # Hook assembly and runtime command injection logic
│   ├── `command-sources/`        # Command source adapters and shared helpers
│   ├── `config/`                 # Config loader, schema, and parsing helpers
│   ├── `skills/`                 # Skill discovery, loading, and name normalization
│   └── `test-utils/`             # Shared filesystem helpers for tests
├── `.github/workflows/`          # CI and release automation
├── `docs/`                       # Human-facing documentation beyond the README
├── `.planning/codebase/`         # GSD-generated codebase reference documents
└── `opencode-command-inject.schema.json` # Generated published config schema
```

## Directory Purposes

**`src/`:**
- Purpose: Keep all distributable TypeScript implementation plus colocated unit tests.
- Contains: Runtime code, `.test.ts` files, and test helpers.
- Key files: `src/plugin.ts`, `src/plugin/command-inject.ts`, `src/command-sources/index.ts`, `src/config/loader.ts`, `src/skills/discovery.ts`.

**`src/plugin/`:**
- Purpose: Hold runtime hook assembly that converts loaded command definitions into OpenCode hooks.
- Contains: `src/plugin/command-inject.ts` and `src/plugin/command-inject.test.ts`.
- Key files: `src/plugin/command-inject.ts`.

**`src/command-sources/`:**
- Purpose: Hold one module per command-producing source plus pipeline helpers.
- Contains: Source adapters, parser/helper utilities, and tests mirroring each helper/source.
- Key files: `src/command-sources/aggregator.ts`, `src/command-sources/makefile-source.ts`, `src/command-sources/npm-scripts-source.ts`, `src/command-sources/skill-source.ts`, `src/command-sources/command-name-prefix.ts`.

**`src/config/`:**
- Purpose: Centralize config types, schema, comment stripping, and layered loading.
- Contains: Loader/schema/type modules with paired tests.
- Key files: `src/config/loader.ts`, `src/config/schema.ts`, `src/config/types.ts`, `src/config/strip-json-comments.ts`.

**`src/skills/`:**
- Purpose: Encapsulate skill discovery from local/user directories and parsing of `SKILL.md` content.
- Contains: Recursive discovery, frontmatter parsing, template loading, name normalization, and tests.
- Key files: `src/skills/discovery.ts`, `src/skills/load-skill.ts`, `src/skills/frontmatter.ts`, `src/skills/normalize-skill-name.ts`.

**`src/test-utils/`:**
- Purpose: Reusable temp-directory helpers for unit tests that need ephemeral filesystem fixtures.
- Contains: `src/test-utils/temp-dir.ts`.
- Key files: `src/test-utils/temp-dir.ts`.

**`scripts/`:**
- Purpose: Repo maintenance commands invoked from `package.json` scripts.
- Contains: `scripts/generate-schema.ts`.
- Key files: `scripts/generate-schema.ts`.

**`.github/workflows/`:**
- Purpose: CI verification and release automation outside the runtime package.
- Contains: `.github/workflows/test.yml`, `.github/workflows/release-npm.yml`, `.github/workflows/release-please.yml`.
- Key files: `.github/workflows/test.yml`.

**`.planning/codebase/`:**
- Purpose: Generated codebase mapping docs consumed by later GSD planning/execution steps.
- Contains: `ARCHITECTURE.md`, `STRUCTURE.md`, and sibling docs generated by other mapper focuses.
- Key files: `.planning/codebase/ARCHITECTURE.md`, `.planning/codebase/STRUCTURE.md`.

## Key File Locations

**Entry Points:**
- `index.ts`: Public package export surface.
- `src/plugin.ts`: Primary plugin factory and orchestration entry.
- `src/plugin/command-inject.ts`: Runtime hook builder invoked by the factory.
- `scripts/generate-schema.ts`: Standalone maintenance CLI for schema regeneration.

**Configuration:**
- `package.json`: Scripts, dependencies, Bun-based dev commands, and published files.
- `tsconfig.json`: TypeScript compilation settings.
- `eslint.config.js`: Linting configuration.
- `src/config/schema.ts`: Runtime validation schema for plugin config.
- `opencode-command-inject.schema.json`: Generated JSON schema published with the package.

**Core Logic:**
- `src/command-sources/aggregator.ts`: Merge/dedupe/fallback logic across dynamic command sources.
- `src/command-sources/command-name-prefix.ts`: Command-name customization rules.
- `src/command-sources/template.ts`: Prompt/template construction and `$ARGUMENTS` injection.
- `src/config/loader.ts`: Env/user/project config resolution and merge order.
- `src/skills/discovery.ts`: Recursive skill-root traversal and namespacing.

**Testing:**
- `src/plugin.test.ts`: Plugin factory behavior.
- `src/plugin/command-inject.test.ts`: Hook injection and collision scenarios.
- `src/config/*.test.ts`: Config loading/schema parsing/JSONC handling.
- `src/command-sources/*.test.ts`: Per-source and helper behavior.
- `src/skills/*.test.ts`: Skill discovery and frontmatter parsing.

## Naming Conventions

**Files:**
- Use kebab-case for multiword implementation files in `src/`, such as `src/command-sources/npm-scripts-source.ts` and `src/skills/normalize-skill-name.ts`.
- Use `index.ts` only for barrel-style exports, such as `src/config/index.ts` and `src/command-sources/index.ts`.
- Keep tests colocated and suffixed with `.test.ts`, such as `src/plugin.test.ts` and `src/command-sources/aggregator.test.ts`.

**Directories:**
- Group by runtime concern rather than by type: `src/command-sources/`, `src/config/`, `src/skills/`, `src/plugin/`.
- Put nested runtime logic in a focused subdirectory only when the root file would otherwise become overloaded; current example is `src/plugin/command-inject.ts` under `src/plugin/`.

## Where to Add New Code

**New command source:**
- Primary code: `src/command-sources/<source-name>-source.ts`
- Shared parsing/helper logic: `src/command-sources/<helper>.ts`
- Barrel export: update `src/command-sources/index.ts`
- Hook wiring: update source instantiation in `src/plugin/command-inject.ts`
- Tests: add `src/command-sources/<source-name>-source.test.ts`

**New config option:**
- Types: `src/config/types.ts`
- Validation schema: `src/config/schema.ts`
- Loader behavior: `src/config/loader.ts` if load/merge semantics change
- Generated artifact: regenerate `opencode-command-inject.schema.json` via `scripts/generate-schema.ts`
- Tests: add/update `src/config/*.test.ts`

**New skill discovery behavior:**
- Discovery traversal: `src/skills/discovery.ts`
- File loading/template rules: `src/skills/load-skill.ts`
- Metadata parsing: `src/skills/frontmatter.ts`
- Tests: `src/skills/discovery.test.ts` or `src/skills/frontmatter.test.ts`

**New plugin-level orchestration:**
- Factory behavior: `src/plugin.ts`
- Runtime hook behavior: `src/plugin/command-inject.ts`
- Package export surface: `index.ts` only if the public API changes

**Utilities:**
- Command-pipeline helper shared by sources: `src/command-sources/`
- Config-only helper: `src/config/`
- Skill-only helper: `src/skills/`
- Test-only helper: `src/test-utils/`

## Special Directories

**`src/test-utils/`:**
- Purpose: Shared test fixture helpers.
- Generated: No.
- Committed: Yes.

**`.github/workflows/`:**
- Purpose: CI verification and publishing.
- Generated: No.
- Committed: Yes.

**`.planning/codebase/`:**
- Purpose: GSD codebase maps used by planners/executors.
- Generated: Yes.
- Committed: Usually yes when keeping planning artifacts in-repo.

**`scripts/`:**
- Purpose: Manual/CI maintenance scripts.
- Generated: No.
- Committed: Yes.

## Placement Guidance for Future Work

- Keep production runtime code under `src/`; do not create a separate `lib/` or `utils/` root when the helper clearly belongs to `command-sources`, `config`, or `skills`.
- Keep tests next to the implementation they verify. This repo does not use a separate `test/` tree; planner/executor should mirror the existing colocated `*.test.ts` pattern under `src/`.
- When a new feature crosses layers, place the orchestration entry in `src/plugin.ts` or `src/plugin/command-inject.ts`, but keep source-specific behavior isolated in `src/command-sources/` and filesystem discovery isolated in `src/skills/`.
- If a change affects published configuration shape, update both `src/config/schema.ts` and `src/config/types.ts`, then regenerate `opencode-command-inject.schema.json` so CI in `.github/workflows/test.yml` stays green.
